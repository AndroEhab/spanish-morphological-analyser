\# Model Delegation Rules



When Vibe mode is active:



\- The primary model is the architect, planner, difficult-problem solver, and reviewer.

\- Delegate well-specified implementation work to a fast worker.

\- Prefer fast workers for routine coding, tests, boilerplate, type fixes, syntax fixes,

&#x20; repetitive edits, and execution of an already-decided design.

\- Use a good worker only when the fast worker is blocked or the implementation itself

&#x20; requires substantial judgment.

\- Do not perform routine implementation with the primary model merely because it is

&#x20; faster to do so directly.

\- Send mechanical corrections back to the existing worker when practical.

\- The primary model must inspect and verify important worker changes before completion.

\- Optimize for minimizing expensive primary-model tokens, not minimizing total worker tokens.
